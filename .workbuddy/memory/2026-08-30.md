## 节点展开动画不生效(需求方反馈)——诊断与修复

现象:点击节点展开看不到出现动画。实测后定位到**三个叠加根因**,已全部修复。

### 根因 1(结构性):roomRender 在渲染末尾立即消费 justArrived
`js/room02.js` 的 `roomRender()` 用 `box.innerHTML = ...` **整块重建**所有节点,
并在结尾立刻 `justArrived = false`。而一次点击内 `roomRender` 常被调用 2~3 次
(`inspect()` 内部一次 + 调用方末尾再显式一次),导致 `.arrive` 只落在随后被
丢弃的中间那次 DOM 上,最终上屏的元素反而没有动画类。
**修复**:改为 `requestAnimationFrame` 延迟到下一帧再清标记——同一任务内的多次
重渲染都带着类,只有最后上屏的那份 DOM 播动画。

### 根因 2:编译关卡两条显形路径漏设 justArrived
`js/engine.js:1421` 的 `compiledHandle` **包装函数**接管了容器开启分支(1423-1454)
并 `return true`,**永不调用 `baseHandle`**;该分支显形内容物时只设 `hidden=false`。
而 1142-1166 / 1197-1226 里此前刚加的 `justArrived = true` 在这条路径上是死代码。
`levelStart()` 散落模式分支(905-921)同样漏设。
**修复**:两处补 `justArrived = true`。

### 根因 3:CSS 重复 transition 声明互相覆盖
`css/styles.css` 的 `.node` 里曾有**两条** `transition`(1036 / 1048),后一条
把前一条整条覆盖,使特意加的 `left/top 0.45s` 位移平滑完全失效(实测
`transitionProperty` 只剩 box-shadow/border-color/opacity/filter/transform)。
**修复**:合并为一条,left/top 得以生效。

## 可复用诊断手法:前端动画"看起来没生效"怎么查
不要靠读代码猜,四步实测(Playwright):
1. **挂钩渲染函数**:若渲染函数是全局 `function` 声明,可直接 `window.render = 包装`,
   内部调用也会走包装(经典脚本顶层函数即 window 属性)。在包装里记录
   "每次渲染后 DOM 中带动画类的元素"。
2. **逐帧采样**:`requestAnimationFrame` 循环 40 帧,记录
   `document.getAnimations().filter(a => a.animationName === 'xxx')` 的
   `length / playState / currentTime`。`currentTime` 一直为 0 或动画数为 0
   即为"没播";`currentTime` 正常推进才是真播了。
3. **区分"标记没设"还是"设了没渲染"**:在渲染函数 entry/exit 各采样一次状态标记,
   对比 DOM 结果,一次就能定位到具体分支。
4. **查重复 CSS 声明**:同一规则里出现两条 `transition`/`animation` 时后者整条
   覆盖前者,静态看不出来。用
   `getComputedStyle(el).transitionProperty` 打印实际生效值来确认。
