# 收藏夹密室 Room 01：未完成的机器

## 设计目标

做一间 10～15 分钟、人工策展的文字密室。玩家不是整理收藏，也不是阅读摘要，而是在一个由收藏构成的工作室里搜索、试错、回访，并让一个三年前保存的想法重新运行。

核心体验：

```text
只看到一个根节点
→ 展开空间
→ 发现可疑物件
→ 学会不同动作
→ 改变房间状态
→ 回访旧节点
→ 在压力下完成操作
→ 打开出口并做选择
```

## 场景结构

开场只暴露一个节点：

```text
未完成的机器
```

点击后展开四个空间节点。空间节点是浮动的，可以任意拖动、排列和聚类；位置保存在本地，成为玩家自己的推理痕迹。所有带有 `parent` 的节点在无限画布式的房间中沿父节点展开，并以连线表达归属；独立道具和合成产物没有父节点，不与空间连线。

```text
未完成的机器
├── 资料架
├── 工作台
├── 黑掉的屏幕
└── 出口
```

### 资料架

第一次打开只出现三个可见物件：

```text
文字密室逃脱
Explorable Explanations
NandGame
```

检查“文字密室逃脱”会得到一个规则提示：

> 物件不会因为被看见而完成。离开以后，再回来看看。

检查“Explorable Explanations”会显示一个不可操作的参数旋钮，提示“解释需要被拨动”。这不是知识问答，而是教玩家寻找可交互状态。

检查“NandGame”后，资料架内部出现一个半遮住的子节点：`nand2tetris`。它必须通过拖动资料架节点来移开遮挡物才能发现，教学自由拖动与层级展开。

### 工作台

第一次打开出现：

```text
Programiz
Vue SFC Playground
锁住的抽屉
```

`锁住的抽屉`不是立即可解的密码锁。点击它只显示三枚空白转盘和一句：

> 三个地方记得你碰过什么。

`Programiz` 和 `Vue SFC Playground` 都能打开原收藏，但只有检查文字内容不会推进状态。它们是后续组合的材料。

### 黑掉的屏幕

第一次点击只显示黑屏和一个电量为 3 的手电筒图标。手电筒必须拖到黑屏上才会消耗一次电量并揭示一小段内容。错误地照亮空白墙面也会消耗电量，但只得到噪声，避免所有资源都无代价。

三次照明内容依次是：

```text
骨架缺失
反馈缺失
顺序缺失
```

当屏幕被重新点亮后，黑屏节点变成 `启动中的机器`，允许回访。

### 出口

出口一直可见，但只显示三层锁：

```text
结构锁 / 反馈锁 / 选择锁
```

点击出口不会给出答案，只会记录玩家已经看到的锁状态。

## 核心谜题链

### 谜题一：结构组合

动作：拖动组合。

把 `NandGame` 拖到 `nand2tetris` 上，生成：

```text
计算机骨架
```

两者都来自真实收藏，关系不是“同主题”标签，而是“从底层结构开始建造”。组合后：

- 资料架变暗，原节点变为已使用物件；
- 工作台重新检查时出现 `旧项目草稿`；
- 出口的结构锁亮起。

错误拖动不会消耗物件，但会产生短暂的机械噪声，告诉玩家系统存在不同动作结果。

### 谜题二：探索规则

动作：连续点击 / 多次拨动。

`Explorable Explanations` 的参数旋钮需要连续拨动三次。每次拨动会改变节点文字，但不会立刻给奖励：

```text
解释 → 变量 → 反馈 → 解释
```

第三次拨动后生成 `探索规则`，并把资料架里原本隐藏的 `回访标记` 暴露出来。玩家回到已经访问过的 `工作台`，才能看到旧项目草稿。

这个谜题的作用是教会玩家：点击过不代表完成，状态变化后必须回访。

### 谜题三：三端口密码

动作：跨空间联动 + 点击计数。

打开 `旧项目草稿` 后，出现一张残缺的操作记录：

```text
左端口：两次短响
中端口：一次长响
右端口：三次短响
```

工作台背后随之出现 `维护间`，里面有三个独立节点：`左端口`、`中端口`、`右端口`。它们初始外观相同，玩家需要点击并听反馈：

- 左端口点击 2 次；
- 中端口点击 1 次并停留半秒；
- 右端口点击 3 次。

正确后生成 `反馈回路`。错误次数不会重置整个房间，只会让对应端口短暂锁定，并在日志里留下“过载”状态。

这借鉴原作三个联动厕所隔间的思想：局部动作简单，谜题关系分散在多个空间。

### 谜题四：QTE 启动

动作：限时拖动。

把 `计算机骨架` 和 `Programiz` 组合后，生成 `可执行逻辑`。把 `可执行逻辑` 拖向 `Vue SFC Playground` 时触发 8 秒 QTE：

```text
反馈正在丢失。把光标拖进亮起的插槽。
```

插槽位置每次略有变化，但会保持明显的视觉和声音提示。成功后生成 `可运行外壳`，失败后：

- 屏幕进入“过热”状态 5 秒；
- 手电筒额外消耗一格；
- 玩家仍可重新尝试，不产生死局。

### 谜题五：有限照明下的回访

当 `可运行外壳` 出现后，屏幕短暂亮起，显示一行被遮挡的文本。玩家需要用剩余手电筒照亮 `资料架` 或 `工作台` 的暗角，找到缺失的第三段记录。

如果玩家之前错误照明浪费了电量，暗角不会消失，而是需要先完成三端口密码来获得一枚临时电池。资源管理会改变路线，但不会让房间不可解。

### 谜题六：出口选择

将 `反馈回路`、`可运行外壳` 和 `未完成的机器` 拖到出口，三层锁全部打开。出口不弹出“恭喜完成”，而是提供三个互斥选择：

```text
继续：生成一个下一步任务
归档：承认项目暂时不值得继续
转化：把这套谜题保存为下一间房的种子
```

选择会改变结尾旁白和房间最后状态。它把收藏转化为行动或有意识的放弃，而不是生成一份总结报告。

## 交互动作表

| 动作 | 用途 | 玩家学到什么 |
| --- | --- | --- |
| 点击节点 | 检查、展开、回访 | 节点有内部结构 |
| 自由拖动 | 摆放、移开遮挡、建立空间记忆 | 节点是空间物件 |
| 拖动到节点 | 组合或触发目标 | 物件存在因果关系 |
| 连续点击 | 拨动旋钮、端口计数 | 状态可能依赖次数 |
| 密码输入 | 出口和抽屉 | 分散线索可以汇合 |
| 限时拖动 | 启动 QTE | 游戏会要求即时反应 |
| 手电照明 | 消耗资源揭示隐藏文本 | 探索有成本 |
| 重新检查 | 获取状态变化后的新信息 | 已访问不等于已解决 |

## 失败与反馈原则

- 错误组合不直接说“错误答案”，只反馈物理或状态结果，例如卡住、噪声、短暂过载。
- 所有失败都可恢复，最多增加时间和资源成本，不制造不可逆死局。
- 正确操作必须改变至少一项可观察状态：新节点、节点文字、声音、亮度、锁、计时器或日志。
- 不把可交互动作藏在自然语言谜语里；首次出现某动作时，先用低风险对象教学。
- 重要线索至少有两种表现方式：文字 + 声音，或节点变化 + 旁白。

## 数据模型方向

房间不是一张收藏卡片列表，而是一个状态图：

```text
RoomNode {
  id, parent, label, children, position,
  visibleWhen, inspectText, actions, state
}

Puzzle {
  id, verb, inputs, preconditions,
  successEvents, failEvents, resetPolicy
}
```

谜题规则、计时、资源和正确答案确定性编排；模型只负责从收藏标题和 URL 生成检查文案、旁白候选和装饰性线索，不负责临场判定唯一解。

## 引导与提示系统

这间房不能完全复制原作“卡住就穷举或看攻略”的体验。玩家需要始终知道还有什么值得观察，但不能被系统直接带着执行答案。

提示绑定当前谜题前沿，每个前沿最多三层：

```text
观察：哪里值得注意？
联想：哪些对象可能有关？
行动：可以尝试什么动作？
```

提示使用四格“观察力”作为软资源：

- 第一级提示不消耗；
- 第二级消耗一格；
- 第三级消耗两格；
- 完成局部谜题后恢复一格；
- 观察力耗尽不会导致死局，只能继续自行探索。

每次提示后进入观察期。玩家必须完成一次有效动作才能请求下一层或下一次提示。有效动作包括：点击新节点、展开空间、拖动节点、回访状态变化的节点、尝试相关机关或完成一个局部谜题。

连续请求提示不会显示三条答案，而是反馈：

> 先让刚才的线索发生一点作用。

提示不直接判定“正确答案”，只逐步减少搜索空间。第三层也只描述动作，不代替玩家完成动作。

## 扩充后的 10～15 分钟流程

首屏只显示 `未完成的机器`。完整流程预计包含 20～25 次有意义的检查、展开或操作：

1. 点击根节点，展开资料架、工作台、黑屏和出口；
2. 探索资料架，检查真实收藏 `文字密室逃脱`、`Explorable Explanations`、`NandGame` 和可选的 `Kaggle`；
3. 检查 `NandGame`，移开遮挡，发现 `nand2tetris`；
4. 拖动 `NandGame` 和 `nand2tetris`，生成 `计算机骨架`；
5. 再检查 `Explorable Explanations`，发现卡住的旋钮；
6. 连续拨动旋钮三次，生成 `探索规则`；
7. 回访工作台，发现状态变化后出现的 `旧项目草稿`；
8. 检查草稿，发现维护间和三个端口；
9. 左端口点击两次，中端口长按一次，右端口点击三次；
10. 生成 `反馈回路`；
11. 打开抽屉密码盘，输入由端口次数构成的 `213`；
12. 获得备用电池；
13. 将 `计算机骨架` 拖到 `Programiz`，生成 `可执行逻辑`；
14. 将 `可执行逻辑` 拖到 `Vue SFC Playground`，触发 8 秒 QTE；
15. 成功后生成 `可运行外壳`；失败会损失一格电量，但可以重试；
16. 用手电筒照亮黑屏，得到启动日志；
17. 在有限照明下回访屏幕后面的暗角，得到顺序线索；
18. 将 `反馈回路` 拖到 `可运行外壳`，生成 `重新启动的机器`；
19. 检查出口，确认六层锁已经响应；
20. 选择继续、归档或转化。

其中若干步骤可以并行探索，玩家不需要严格按线性顺序执行；但状态锁会保证不会出现无法理解的跳跃。

## Demo 完成标准

在首次实现中只做这一间房，不做全量导入和自动出题。完成标准是：

1. 首屏只有一个根节点；
2. 至少三次点击展开子结构；
3. 节点可自由拖动并保留位置；
4. 至少包含一次组合、一次点击计数、一次密码、一次 QTE、一次有限资源；
5. 至少有一次回访改变旧节点；
6. 错误操作可恢复且有反馈；
7. 玩家能在 10～15 分钟内完成并理解最后三个选择；
8. 不需要读完任何收藏内容，不需要写总结；
9. 完成主线需要至少 10 分钟的探索，而不是五次配对点击；
10. 提示按钮能降低卡关风险，但不能被连续点击刷出答案。
